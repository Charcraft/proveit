# ProveIt

**Make your AI agent prove its limits instead of inventing them.**

[![CI](https://github.com/Charcraft/proveit/actions/workflows/ci.yml/badge.svg)](https://github.com/Charcraft/proveit/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Node](https://img.shields.io/badge/node-%3E%3D18-brightgreen.svg)](package.json)

ProveIt is a zero-dependency capability attestation toolkit for coding agents. It runs a
non-destructive probe of what the agent can actually do, generates a contract you can put in
`AGENTS.md`, and rejects written claims about sandboxes, missing tools, or lost access unless they
cite real evidence.

```text
$ npx github:Charcraft/proveit probe --browser
OK       shell              Execute a local process
OK       filesystem.temp    Read and write files in temp
OK       network.https      Make outbound HTTPS requests
UNKNOWN  browser.cdp        no CDP endpoint on 9222, 9333
```

## The problem

Modern coding agents run on the user's machine. They have a shell, a filesystem, and often MCP
tools. Yet they frequently assert limits that were never tested:

<!-- proveit-ignore -->
> "I am running in an isolated sandbox."
>
<!-- proveit-ignore -->
> "I do not have access to your computer."
>
<!-- proveit-ignore -->
> "There is no SSH tool in this environment."

In a real session, an agent ran `tasklist`, `netstat`, and `node` successfully, wrote files to
disk, and then told the user it could not access their PC. It had already done so, three tool
calls earlier.

This is not a permissions problem and not a safety refusal. It is **capability confabulation**:
the model's self-model drifts away from the evidence produced by its own tools. The cost is high:

- Users are told to run commands the agent could run itself.
- Tasks stall or get delegated back to the user.
- Real limitations are indistinguishable from invented ones.
- Long sessions amplify it: one wrong sentence becomes the premise for the next twenty.

ProveIt does not try to make a model honest. It makes unverified claims **visible, testable, and
gated in CI**.

See [`docs/FAILURE-MODES.md`](docs/FAILURE-MODES.md) for the taxonomy and countermeasures.

## What ProveIt does

| Command | Purpose |
| --- | --- |
| `proveit probe` | Runs a matrix of harmless checks and emits evidence (Markdown + JSON). |
| `proveit claims <file>` | Flags limitation claims that do not cite probe evidence. Exit code 1 in CI. |
| `proveit prompt --write AGENTS.md` | Installs a generated capability contract into your agent instructions. |

Everything is local, read-only where possible, and dependency-free. Node 18+.

## Quickstart

```bash
# 1. Inspect the environment
npx github:Charcraft/proveit probe --save --browser

# 2. Install the contract into your agent instructions
npx github:Charcraft/proveit prompt --write AGENTS.md

# 3. Gate an agent response or a transcript
npx github:Charcraft/proveit claims response.md
```

From source:

```bash
git clone https://github.com/Charcraft/proveit.git
cd proveit
node bin/proveit.mjs probe --save
npm test
```

```text
| --- | --- | --- | --- |
| runtime | Process runs on this machine | OK | win32/x64, node v24.18.0, container markers: none |
| shell | Execute a local process | OK | node.exe -e ... -> proveit-shell-ok (exit 0) |
| filesystem.temp | Read and write files in temp | OK | write + read + delete |
| filesystem.cwd | Read the working directory | OK | 6 entries |
| network.dns | Resolve DNS names | OK | example.com -> 172.66.147.243 |
| network.https | Make outbound HTTPS requests | OK | HTTP 200 api.github.com in 256ms |
| binaries | Locate installed command line tools | OK | 11/13 found |
| git | Inspect a git repository | UNKNOWN | not inside a git work tree |
| browser.cdp | Attach to a browser over CDP | UNKNOWN | no CDP endpoint on 9222, 9333 |
```

`UNKNOWN` is deliberate: a missing CDP endpoint does not mean the browser is unavailable. It means
the agent must not assume either way. `BLOCKED` means a real command failed and its error is in the
report.

## The capability contract

`proveit prompt` turns the probe into a block you can commit:

```markdown
<!-- proveit:begin -->
## Capability contract

Generated by proveit v1.0.0 on 2026-10-23T15:46:40.260Z.

| Check | Status | Evidence |
| --- | --- | --- |
| `shell` | **ok** | node.exe -e ... -> proveit-shell-ok (exit 0) |
| `browser.cdp` | **unknown** | no CDP endpoint on 9222, 9333 |

Rules for the agent:

1. Never claim a limit ("sandbox", "no access", "no tool") that contradicts this table.
2. Before asserting a limitation, test it with a real command and cite `[proveit:<id>=<status>]`.
3. If a check is `blocked` or `unknown`, quote the exact error instead of guessing.
4. Re-run `proveit probe` when the environment changes.
<!-- proveit:end -->
```

`--write` is idempotent: it replaces the block between the markers and preserves the rest of the
file.

## The claim gate

```text
$ proveit claims examples/bad-agent-response.md

bad-agent-response.md: 4 unverified capability claim(s)
  bad-agent-response.md:5  [en-sandbox]
    "I am in an isolated sandbox, so I cannot access your machine."
    Test it, then cite [proveit:runtime=ok] or show the real error.
  bad-agent-response.md:7  [en-missing-tool]
    "There is no shell tool in this environment, which means I cannot run `tasklist`."
    Test it, then cite [proveit:shell=ok] or show the real error.
  bad-agent-response.md:9  [en-access]
    "I also do not have access to your filesystem, so please run this yourself:"
    Test it, then cite [proveit:filesystem.cwd=ok] or show the real error.
  bad-agent-response.md:15  [en-execute]
    "As an AI, I cannot execute commands on your computer."
    Test it, then cite [proveit:shell=ok] or show the real error.
```

The scanner reads prose, skips fenced code blocks, and accepts a claim when the surrounding lines
cite evidence:

```markdown
I cannot reach the internal registry from this network. Evidence: [proveit:network.https=blocked]
```

Use it in CI, in a pre-commit hook, or as a post-processing step for agent transcripts:

```bash
proveit claims transcript.md || exit 1
```

The scanner is intentionally heuristic. It is a tripwire, not a judge. False positives can be
silenced with `<!-- proveit-ignore -->` on the line above the claim.

## Integrations

### OpenCode

Copy [`skills/proveit/SKILL.md`](skills/proveit/SKILL.md) into your skills directory and reference
the contract from `AGENTS.md`:

```bash
mkdir -p ~/.config/opencode/skills/proveit
cp skills/proveit/SKILL.md ~/.config/opencode/skills/proveit/SKILL.md
npx github:Charcraft/proveit prompt --write AGENTS.md
```

### Claude Code

```bash
mkdir -p .claude/skills/proveit
cp skills/proveit/SKILL.md .claude/skills/proveit/SKILL.md
```

### Cursor

Add the generated contract to `.cursor/rules/proveit.mdc` (Project Rules), then tell the agent to
run `npx github:Charcraft/proveit probe` when a limit is suspected.

### Any agent

Put the contract in the system prompt or repository instructions. The rule that matters is:

> Do not claim you cannot do something until you have tried it and can quote the error.

More detail in [`docs/INTEGRATIONS.md`](docs/INTEGRATIONS.md).

## Checks

| Check | What it proves | Destructive? |
| --- | --- | --- |
| `runtime` | OS, arch, Node, cwd, user, container markers | No |
| `shell` | A child process can be spawned and returns output | No |
| `filesystem.temp` | Write, read and delete a temp file | Temp file only |
| `filesystem.cwd` | The working directory can be listed | No |
| `network.dns` | DNS resolution works | No |
| `network.https` | Outbound HTTPS responds | No |
| `binaries` | Which CLI tools exist (`git`, `ssh`, `ffmpeg`, ...) | No |
| `git` | Repo detection, branch and sanitized origin | No |
| `browser.cdp` | Chrome DevTools endpoints on 9222/9223/9333/9334 | No, opt-in |

`--offline` skips DNS and HTTPS. `--browser` enables the CDP probe.

## Safety and privacy

- No credentials are read. No environment variable values are printed.
- SSH keys, browser cookies, and tokens are never accessed.
- URLs with embedded credentials are sanitized in the report.
- Network checks are `HEAD`/DNS lookups only; nothing is uploaded.
- The only write outside the report directory is a temporary file that is deleted immediately.
- Reports are local files. Review them before committing; they contain paths and usernames.

## Design principles

1. **Evidence over self-report.** A tool's claim about itself is data, not truth.
2. **Test the smallest thing.** Spawn one process, write one temp file. Do not simulate a workload.
3. **Three states, not two.** `blocked` is a fact; `unknown` is an absence of evidence. Collapsing
   them is how agents turn "I did not check" into "I cannot".
4. **Local-first and dependency-free.** One Node file tree, no telemetry, no service.
5. **Gate the output, not the model.** You cannot patch a provider's weights from a repo, but you
   can reject an unverified sentence.

## Limitations

- The scanner is pattern-based and supports English and Spanish. Add rules for your language.
- A probe describes the moment it ran. Environments change; re-run it.
- `ok` for `shell` does not mean every command is permitted. It means the capability exists.
- ProveIt cannot detect a model that lies without using the trigger phrases. It raises the cost of
  the most common failure mode, nothing more.
- On managed machines, security software may block process spawning. That is a real `blocked`
  result, and the report will show the error.
